1. 本地优先原则

ArchieLink 的核心设计是本地优先：网络诊断、连接建立、健康检查和回滚全部在你的设备上执行。云端只承载订单、授权、设备注册、撤销和持续增值服务，不承载用户网络流量，不存储本地秘密。

断网时 down 和 rollback 永远可用——安全恢复不依赖云端，也不向云端询问。

2. 我们绝不收集的数据

以下数据在任何情况下不进入云端，也不被产品读取：

  • 你的网络流量与 DNS 查询内容（隧道由 Cloudflare 依据你自己的配置建立，我们不经手流量）。
  • 浏览器 Cookie、支付信息（支付密码/验证码/完整支付凭据）、系统登录凭据。
  • WireGuard 私钥与完整配置（仅存在于你设备的受保护文件或系统密钥库中）。
  • 你本地服务的响应正文。

4. 云端控制面存储的数据

购买或激活后，服务端为履行授权需要保存：

  • 订单：订单号、计划、金额、支付交易号、凭证哈希、履约状态、创建时间。
  • 订阅：计划、状态、订阅年度起点、撤销标识。
  • 设备注册：安装 ID、设备公钥、注册时间、名额消耗标记、注册事件时间戳（用于设备池限速）。

服务端不保存：支付密码、验证码、商户私钥、完整支付凭据、你的网络配置或任何流量数据。支付真实性由支付平台侧完成，我们只接收交易结果。

5. 服务端日志

公网网关保留访问日志，内容为来源 IP、时间、请求路径、状态码，仅用于限流、滥用防护和安全审计。当前配置为每日轮转、保留 52 天。应用侧不记录用户网络内容。

6. 跨设备只读会话

跨设备体检采用只读会话设计：

  • 一次性配对码，目标设备显示一次，服务端不留存。
  • 临时自签证书与临时密钥仅存在于内存，会话结束即消失。
  • 远程调用白名单只有只读诊断（检测/计划/体检），无 shell、无写操作、无文件访问。
  • 目标设备一次会话只接受一个连接，配对码错误同样立即关闭（fail-closed）。

7. 数据留存与删除

  • 设备移除：订阅持有人可在设备管理中移除设备；被移除设备的租约在下次同步时失效。
  • 退款/撤销：退款或撤销事件后服务端停止续租并推进撤销；订单记录按平台交易对账要求保留。
  • 删除申请：预发布阶段经购买渠道公布的官方支持渠道受理；正式支持渠道随产品正式发布公布。

本政策变更将在发布渠道公告；重大变更（数据类别或用途新增）将在产品内提示。历史版本存档于版本库。

ArchieLink — Privacy Policy

Version v1.0 ｜ Effective date: 2026-11-22 ｜ Scope: the archielink CLI, companion apps on all platforms, and the cloud control plane

1. Local-First Principle

ArchieLink is designed local-first: network diagnostics, connection setup, health checks, and rollback all run on your device. The cloud only carries orders, licensing, device registration, revocation, and continuous value-added services. It never carries user network traffic and never stores local secrets.

When you are offline, down and rollback always work — safe recovery never depends on the cloud.

2. Data We Never Collect

The following data never reaches the cloud and is never read by the product:

  • Your network traffic and DNS query contents (the tunnel is established by Cloudflare based on your own profile; we never handle your traffic).
  • Browser cookies, payment information (payment passwords / verification codes / full payment credentials), or system login credentials.
  • WireGuard private keys and full profiles (they exist only in protected files or the system key store on your device).
  • Response bodies of your local services.

4. Data Stored in the Cloud Control Plane

After purchase or activation, the server stores what is required to fulfill your license:

  • Orders: order number, plan, amount, payment transaction number, credential hash, fulfillment status, and creation time.
  • Subscriptions: plan, status, subscription-year start, and revocation epoch.
  • Device registrations: installation ID, device public key, registration time, quota-consumption flag, and registration event timestamps (used for device-pool rate limiting).

The server does not store: payment passwords, verification codes, merchant private keys, full payment credentials, your network profiles, or any traffic data. Payment authenticity is verified by the payment platform; we only receive the transaction result.

5. Server Logs

The public gateway keeps access logs containing source IP, time, request path, and status code, used only for rate limiting, abuse protection, and security auditing. Logs rotate daily and are retained for 52 days. The app itself never logs your network contents.

6. Cross-Device Read-Only Sessions

Cross-device checkups use a read-only session design:

  • One-time pairing code, shown once on the target device and never stored on the server.
  • Temporary self-signed certificates and keys exist only in memory and vanish when the session ends.
  • The remote-call whitelist contains only read-only diagnostics — no shell, no writes, no file access.
  • The target device accepts exactly one connection per session; a wrong pairing code closes the session immediately (fail-closed).

7. Data Retention and Deletion

  • Device removal: the subscription holder can remove a device in device management; the removed device's lease expires at the next sync.
  • Refund / revocation: after a refund or revocation, the server stops renewing the lease and advances the revocation epoch; order records are retained as required for platform reconciliation.
  • Deletion requests: during the pre-release stage, handled via the official support channel published with your purchase; the formal support channel will be published at general availability.

9. Policy Changes

Changes to this policy will be announced on our release channels; material changes (new data categories or purposes) will also be surfaced in the product. Historical versions are archived in the repository.

10. Scope and Contact

This policy applies to the archielink CLI, companion apps on all platforms, and the cloud control plane. During the pre-release stage, contact us via the channel published with your purchase; the formal support channel will be published at general availability.
