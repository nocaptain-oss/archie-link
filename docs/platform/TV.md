# 汪连 ArchieLink｜外网访问专家 — Android TV 与鸿蒙智慧屏规格

**状态：** Accepted v1.0；VIDAA D2 已由用户整体验收，TV companion `0.4.0`
**日期：** 2026-11-05  
**产品规格：** [SPEC.md](../product/SPEC.md)
**路线图：** [ROADMAP.md](../product/ROADMAP.md)

## 1. 产品判断

电视端是高价值场景，因为用户目标非常明确：

- 在大屏上访问 YouTube 和其他外网视频
- 不依赖手机投屏
- 家庭成员可以独立使用
- VPN 启动后，已有电视应用或浏览器可以直接受益

电视端的付费价值高于“教开发者在终端里安装 WARP”，但也带来更高的平台审核、输入交互和播放器兼容成本。

建议拆成两个阶段：

1. **电视 VPN 核心**：进入 V1.0 前，完成系统 VPN、遥控器交互、网络验证和最小浏览入口。
2. **电视浏览器增强**：放在 V1.0 后，开发专门的大屏浏览器体验。

## 2. 目标平台

| 平台 | 核心支持 | 浏览器策略 |
|---|---|---|
| Android TV / Google TV | Android `VpnService` 应用 | 优先调用已安装 YouTube 或系统浏览器 |
| 国内 Android 电视 | 条件性支持，取决于系统 VPN API 和应用安装权限 | 通常需要内置或引导安装浏览器 |
| HarmonyOS 智慧屏 | 条件性支持，取决于设备是否开放 `VpnExtensionAbility` | 优先系统浏览器；无可用浏览器时进入引导模式 |
| 电视盒子 | 按 Android TV 适配器检测 | 不承诺所有厂商固件 |

电视、车机、手表虽然都属于大屏或 HarmonyOS 设备族，但产品策略完全不同。本规格只覆盖电视和智慧屏。

## 3. 核心用户流程

```text
安装电视伴侣应用
  -> 首次 VPN 授权
  -> 选择连接
  -> 验证外网视频页面可达
  -> 打开已有 YouTube 应用或最小浏览器入口
  -> 停止连接并恢复原网络
```

如果设备没有 YouTube 应用、Google 服务或可用浏览器，必须明确告诉用户缺少内容入口，不能只显示“VPN 已连接”就结束。

## 4. V1.0 前必须完成

### TV-001 电视伴侣应用

- 电视端启动页
- 遥控器方向键、确认键和返回键操作
- VPN 启动、停止和状态展示
- 首次用户授权
- 当前连接和错误信息
- 大字号、强焦点态和低文字密度
- 应用分流选择的持久化条目在应用卸载后自动清理：`excluded`/`removed`
  集合中包名已不在设备上的条目，在下一次读取选择时被剪除并回写；
  清理以"是否仍安装"为准，不区分系统/非系统应用

### TV-002 网络能力

- Android TV：使用 `VpnService`
- HarmonyOS 智慧屏：使用 `VpnExtensionAbility`，前提是设备开放该能力
- 全隧道或按需分流
- DNS 配置
- 本地视频应用保护
- 休眠、唤醒和网络切换
- 检测已有 VPN

### TV-003 内容入口检查

连接后检查：

- YouTube 网页或视频服务是否可访问
- 系统浏览器是否存在
- 已安装 YouTube 客户端是否存在
- Google 服务是否可用（仅 Android TV）
- 当前设备是否只能通过网页访问

结果必须区分为：

- `ready_with_app`
- `ready_with_browser`
- `needs_browser`
- `needs_google_services`
- `unsupported`

实施契约（2026-11-26 定稿，随浏览器引导安装一并实现）：

- 检测在 TV 伴侣内完成，输入为 `PackageManager` 已安装包查询，不发起网络请求。
- 浏览器识别采用已知包名清单 + 默认 URL handler 兜底。**选择优先级：
  电视原生、遥控器友好的浏览器在前**（V1.1.2 增量修正，2026-11-26
  用户人工验证发现系统浏览器需鼠标操作，毁了仪式时刻）：TV Bro
  （`io.github.tfederico.tvbro`）→ Phlox（`com.phlox.tvwebbrowser`）
  → Firefox TV → Firefox → Chrome → 系统浏览器
  （`com.android.browser`，鼠标/触屏向，仅作最后兜底）；默认
  `http/https` handler 存在且可启动时即使不在清单内也计为可用浏览器
  （兜底场景，仪式体验不保证）。
- 内容入口识别 YouTube TV 客户端（`com.google.android.youtube.tv` 等）与
  SmartTube 开源客户端（`org.smarttube.stable` / `org.smarttube.beta` /
  `app.smarttube.fdroid` 及旧版 `com.liskovsoft.smarttubetv` /
  `com.liskovsoft.smarttubetv.beta`）。SmartTube 无需 Google 服务，
  检测到即计 `ready_with_app`（V1.1.1 增量，2026-11-26 用户拍板）。
- 应用市场识别用于引导安装：当贝市场（`com.dangbei.market` 等）与
  系统 market 包；存在时引导页提供一键跳转市场搜索。
- 状态判定顺序：YouTube 客户端或 SmartTube 存在 → `ready_with_app`；
  有可用浏览器 → `ready_with_browser`；两者皆无 → `needs_browser`
  （无论有无 GMS，先解决浏览器；无 GMS 的设备在引导页提示 YouTube
  客户端不可装，并提供 SmartTube 替代指引，见 §5.1）。
  `needs_google_services` 保留为枚举，V1.1 不单独发出——仅当
  出现「浏览器可用但用户明确需要 YouTube 客户端」的场景时再启用。

### TV-004 最小浏览入口

V1.0 前只做最小闭环：

- 打开系统默认浏览器
- 打开指定 URL
- 通过手机二维码或局域网页面辅助输入网址
- 记住最近访问的 URL
- 返回电视伴侣应用

不在 V1.0 前重做完整浏览器。

实施裁剪（2026-11-26 用户拍板）：扫码输入与"记住最近 URL"随 V1.1
浏览器引导安装暂缓——该版本目标是为"还没有可用浏览器"的电视提供通用
解决方案，不重做浏览器交互。最小闭环保留：伴侣内"打开浏览器"入口
（启动默认或选定的浏览器）与返回键回伴侣。

## 5. V1.1：电视浏览器引导安装

### 5.1 浏览器引导安装（本轮范围，2026-11-26 用户拍板）

目标：为"电视上还没有可用浏览器"的通用场景提供可执行的引导安装
方案，不依赖特定品牌固件，不内嵌浏览器内核。

决策背景：VIDAA 真机上 TV Bro 运行稳定；内嵌 10-foot 浏览器
（WebView/Chromium 系）在该固件存在空白页与进程崩溃，工程成本高、
收益低。V1.1 重心从"自研浏览器增强"转为"引导用户装好并打开已验证
的第三方浏览器"。

功能：

- TV-003 检测（见 §4 实施契约）：主界面展示当前内容入口状态
- `needs_browser` 时进入 TV 端引导安装页：
  - 检测到应用市场（当贝市场等）：一键跳转市场搜索页，搜索推荐浏览器
  - 无市场：分步指引（官网/GitHub 下载 APK → U 盘/文件管理器安装 →
    允许未知来源），文案为大字、低密度、遥控器可逐项聚焦
  - 全程不自动下载、不静默安装；安装动作由用户在市场或系统安装器完成
- 安装完成返回伴侣后自动重检（`onResume` 重跑检测），状态从
  `needs_browser` 变为 `ready_with_browser`
- 主界面提供"打开浏览器"快捷入口：启动默认或选定的浏览器，返回键回伴侣
- 推荐浏览器：TV Bro（用户 VIDAA 实机长期稳定）；系统浏览器可用时
  作为首选（免安装）

V1.1.1 增量（2026-11-26 用户拍板）：

- **SmartTube 引导**：无 GMS 设备的引导安装页在浏览器指引之外提供
  SmartTube（开源 YouTube 电视客户端，无需 Google 服务）安装指引。
  SmartTube 官方不在任何应用商店发布，市场内同名应用可能为仿冒；引导
  只指向官方 GitHub Releases（`yuliskov/SmartTube`），不提供市场搜索
  跳转。安装方式与浏览器手动路径一致（U 盘 + 文件管理器），全程不自动
  下载、不静默安装。
- **主界面简洁化**：内容入口就绪（`ready_with_app` / `ready_with_browser`）
  时主界面不显示内容入口状态行与任何内容入口按钮，界面回归简洁；仅
  `needs_browser` 时显示橙色警示状态行与"安装浏览器引导"按钮。V1.1 的
  "打开浏览器"快捷入口随本增量移除——浏览器装好后用户从电视桌面直接
  打开，无需经伴侣中转（原 §5.1"主界面提供打开浏览器快捷入口"条目废止）。
- **首连 ADB 引导**：见 §5.3。

明确不做：

- 不内嵌浏览器内核，不做地址栏、扫码输入、UA 切换（原 V1.1 浏览器
  增强包，见 §5.2）
- 不自动下载或静默安装任何 APK
- 不承诺所有电视固件都能完成安装（安装权限受限的固件明确提示，
  不卖"可能能用"）

商业化：随调试包免费（2026-11-26 用户拍板）；付费授权集成延后到
TV 正式发布。

验收（VIDAA 真机，Android 9）：

1. `pm disable-user --user 0` 模拟无浏览器（此 ROM `pm hide` 系统应用被
   MANAGE_USERS 拒绝）→ 主界面状态为 `needs_browser` → 引导安装页完整可达
2. 恢复系统浏览器（`pm enable`）→ 返回伴侣自动重检为 `ready_with_browser`
3. "打开浏览器"入口启动系统浏览器，返回键回伴侣（V1.1.1 起该入口移除，
   本条改为：就绪态主界面无内容入口状态行与按钮残留）
4. 有市场设备路径：引导页跳转市场搜索（VIDAA 无当贝市场时以检测
   逻辑单测与文案审查替代真机步骤）
5. 引导页全程遥控器可操作，焦点态清晰
6. V1.1.1：安装 SmartTube 后重检为 `ready_with_app`，主界面无警示残留；
   卸载后回到 `needs_browser` 警示（真机 adb install/uninstall 验证）

### 5.2 电视浏览器增强包（延后，可选）

原 V1.1 全量浏览器功能保留为独立候选阶段，进入开发前须重新立项
（规格+计划）：

- 专为 10-foot UI 设计的地址栏
- 遥控器焦点导航
- 手机扫码输入搜索词和网址
- YouTube 网页快捷入口
- 视频全屏和播放控制
- 历史记录、收藏和主页
- User-Agent 切换
- 页面缩放和视频兼容模式
- 崩溃恢复
- DRM、证书和区域限制诊断
- 广告和跟踪保护策略

这些功能涉及浏览器内核、网页兼容、视频播放和遥控器交互，开发与测试成本明显高于 VPN 核心；仅在第三方浏览器方案无法满足用户时评估启动（2026-11-26 用户拍板：TV Bro 在 VIDAA 长期稳定，暂无启动动机）。

### 5.3 首连 ADB 引导（V1.1.1，2026-11-26 用户拍板）

电视伴侣的安装与配置依赖局域网 ADB；多数国内电视出厂未开启 ADB，
首次连接必须由人类用遥控器完成开启动作，agent 不得编造键序。

要求：

- 详尽开启指引承载于 `skills/archie-link/SKILL.md` Android TV 节
  （public），覆盖至少三条路径：新 Vidda（JUUI）的"商场模式 →
  开发者模式"、老 VIDAA 的"声音平衡 1969 → 工厂模式 Tofac U→M →
  隐藏开发者选项"和通用 Android TV 的"连点版本号"。老 VIDAA 工厂
  模式路径必须附带 M 模式副作用警告（投屏等功能可能异常，完成后切回
  U 模式）。
- 引导必须形成交接闭环：人类确认"ADB 已开启 + 电视 IP"后，agent 接手
  `adb connect <ip>:5555` → 人类在电视端批准"允许 USB 调试"（建议勾选
  始终允许）→ agent 以 `adb devices` 验证后继续 `archielink device
  discover --json`。任一步失败回到对应指引重试，不静默跳过。
- 现场菜单与指引不符时，agent 向用户求证实际所见菜单，不猜测键序。

### 5.4 首次连接「Hello World」仪式（V1.1.2，2026-11-26 用户拍板）

VPN 通道在电视上首次健康连接成功是产品的「Hello World」时刻：引导用户
亲手按遥控器确认键打开浏览器 Google 页面，亲眼看见网页加载——用仪式感
强化「付费是值得的」。这个瞬间只有浏览器能创造（视频应用给不了）。

契约：

- 触发条件（三者同时满足，持久化标志 `first_visit_done` 控制）：
  ① VPN `connected` 且健康检查 `pass`；② 存在可用浏览器
  （`browserPackage != null`，SmartTube-only 设备不触发——仪式瞬间属于
  浏览器）；③ 本机从未完成过该仪式。
- 呈现：主界面叠加全屏仪式层（半透明暗背景 + 居中卡片）：庆祝文案、
  说明文案、主按钮「打开新世界」（显示时自动获得焦点，遥控器确认键
  即激活）、「按返回键跳过」提示。文案遵循 NAMING.md（不使用翻墙/
  机场/梯子/突破限制等禁词）。
- 按确认键：持久化完成标志 → 以 `ACTION_VIEW
  https://www.google.com` 打开检测到的浏览器（地址栏直接呈现
  Google 地址，等同自动注入；URL 加载即「新世界」瞬间）→ 返回键回
  伴侣。启动失败（ActivityNotFoundException 等）提示且不置完成标志，
  可重试。
- 按返回键：本次会话内跳过（不持久化完成标志）——误按返回不会永久
  失去仪式；下次连接周期可再现。按确认键完成才是永久完成。
- 不自动打开浏览器：用户亲手按确认键是仪式的核心，agent/应用不得
  代劳。
- 仪式打开的浏览器按 §4 电视原生优先级选取（V1.1.2 增量修正，
  2026-11-26 用户人工验证发现系统浏览器需鼠标操作，毁了仪式时刻；
  该电视实况 Phlox 在装，仪式改用 Phlox 类遥控器友好浏览器）。
- 已知限制：Google 首页在仪式中正常加载（「新世界」瞬间成立）；
  继续搜索时 Google 可能因 WireGuard/WARP 共享出口 IP 信誉弹出
  人机验证页，且验证页未必可用遥控器完成——仪式目标是首页加载本身，
  不承诺搜索无验证；此为免费线路的固有行为，不在伴侣侧规避。
- 无浏览器设备不触发（`needs_browser` 引导安装流程另行覆盖；装好
  浏览器并首次健康连接后仪式自然到来）。

验收（VIDAA 真机）：

1. 清除仪式标志（或首次安装态）→ 真按键连接 VPN → 健康通过后仪式层
   出现，主按钮带焦点
2. 按确认键 → 浏览器打开 Google 页面 → 返回键回伴侣 → 仪式层消失
3. 断开重连 → 仪式层不再出现（标志已持久化）
4. 返回键跳过路径：清除标志重现仪式 → 按返回键 → 本次会话不再出现

## 6. Android TV 边界

- Android TV 使用 Android VPN 服务，但仍需验证具体电视固件。
- 国内 Android 电视可能没有 Google Play Services 和 YouTube 客户端。
- 2026-11-07 Hisense VIDAA TV（Android 9）没有 `com.android.vpndialogs.ConfirmDialog`，
  `VpnService.prepare` 返回的系统授权 Activity 不存在。此类固件默认报告 `vpn_unsupported`；
  技术用户可显式执行 `archielink device authorize-vpn --yes`，仅为本调试包设置
  `ACTIVATE_VPN` AppOp，完成后用 `revoke-vpn --yes` 恢复。不得静默设置该权限。
- 同一台 VIDAA TV 已完成真实 WARP 数据面验证：WireGuard 握手成功、浏览器加载
  外网页面、ADB 全程在线；VPN 使用公网路由拆分和应用白名单，避免接管 ADB、局域网
  和系统网络栈。
- TV 浏览器兼容性差异明显：`com.android.browser` 可加载 Google NCR、YouTube 搜索
  和 Facebook；`com.phlox.tvwebbrowser` 与 Chromium 在该固件上存在空白页/进程崩溃；
  TV Bro（`io.github.tfederico.tvbro`）经用户长期实机使用稳定，为引导安装的首选推荐。
- ChatGPT Web 对该 WARP 出口 IP 返回 “Unable to load site / try turning VPN off”，
  属于站点侧 VPN 策略，不是隧道故障。
- VPN 应用白名单覆盖全部普通应用和所有可启动的系统电视应用；仅保留 ADB、系统
  设置、SystemUI、VPN 管理界面和伴侣自身直连，避免控制通道被隧道接管。
- 电视应用内提供白名单管理页，可按 UID 分组逐项启停、全选或全不选；仅 appId ≥ 10000
  的普通 UID 可被转发，特权系统 UID 不得进入 VPN。
- 电视 UI 使用连接仪表视觉：品牌、设备与系统信息进入顶栏，仪表和操作区在主区域分开；
  主内容整体略向左平衡，顶栏中文使用明亮橙色；遥控器焦点有明确边框和轻微缩放。
  连接路径使用直线，不在电视和地球下显示说明文字。右侧四个操作按钮整体不高于左侧
  连接图案，并与图案区垂直居中对齐。
- 仪表中心光晕必须与中央状态符号同心，不允许通过下移圆心换取顶部空间；光晕使用宽椭圆
  在绘制区内完整淡出，启用抖动，避免低分辨率、低色深电视出现明显色带或圆形裁切边界。
- 连接后本机屏幕点亮、地球持续旋转；连接中仅让路径流动；未连接/阻断使用红色 X，
  不使用黑色圆形底。系统减少动画时保留静态终态。状态文案使用用户语言，不显示
  `pass` 等工程字段：连接后为“通信成功 · N 个应用可访问外网”，断开时为
  “N 个应用待访问外网”。
- 白名单使用整行焦点列表，避免手机上常见的小复选框和密集表单。顶栏右侧提供“添加应用”
  入口，列出系统内所有尚未加入清单的应用；首次安装时清单为空，必须由用户主动添加。
  添加页不显示副标题和“完成”按钮，顶栏覆盖滚动项，确认添加后停留并继续选择，返回键
  才退出。该页不显示已选择数量。菜单键删除使用深色确认层，不使用系统白底菜单，确认
  按钮沿用整体青灰色系，弹窗顶部圆角与整体卡片一致。焦点从最后一项进入底栏三按钮，
  左右键在三按钮间切换。
- “添加应用”只列出值得接入外网的应用：浏览器、海外视频/音乐、海外应用分发安装、
  视频加速/代理、已知海外网络服务；过滤相册、相机、日历、时钟、通讯录、文件管理、
  桌面和国产视频等本地或无必要应用。游戏保留在推荐清单中，因为联机、排行榜、云存档
  和更新可能依赖外网；用户仍可不添加。
- 系统桌面名称使用“ArchieLink 汪连”，不使用 `Companion`。图标使用代码绘制的网络
  工程师狗：深墨青底、黄铜狗头、玉石半框 AR 眼镜和右侧单侧骨传导耳麦，短麦臂靠近
  嘴侧，居中保持单一识别主体。当贝桌面忽略 `android:banner` 并按长卡比例承载
  `android:icon`，因此电视入口使用 16:9 的 `tv_banner` 作为主图标；`ic_launcher`
  只保留给 `roundIcon` 和方形图标场景，不再在长卡内叠加第二层方块或流程示意图。
- 顶栏和底栏使用不透明主背景色并位于列表上层，避免滚动或焦点缩放的行覆盖导航区域。
- VIDAA TV 真机已验证 22 个应用同时转发、一键连接/断开和 ADB 共存。断开时必须释放
  wireguard-go 继承 TUN 后父进程保留的 fd 0，否则 VPN 接口会残留。
- 没有 GMS 时，VPN 成功不等于 YouTube 可用。
- 需要验证侧载、应用商店和企业设备策略。
- 需要验证遥控器、待机、HDMI 切换和低内存行为。

## 7. HarmonyOS 智慧屏边界

官方文档确认智慧屏属于 HarmonyOS 应用目标设备，并提供智慧屏应用和遥控器交互指导。

但当前官方文档没有明确保证所有智慧屏都开放 `VpnExtensionAbility`，因此：

- 必须在真实智慧屏上验证 VPN Extension 能力。
- 不支持时进入 `guided` 或 `unsupported`。
- 系统浏览器缺失时进入 `needs_browser`。
- 不能假定手机版伴侣应用可以直接安装到智慧屏。

## 8. 网络与播放保护

需要保留：

- 国内视频应用直连
- 本地局域网设备直连
- 投屏和 DLNA 流量保护
- 系统更新和支付域名保护
- 家长控制和企业策略

连接后需检查：

- 外网视频页面
- 国内视频应用
- 投屏发现
- 本地路由器管理页面

## 9. 验收

### 电视 VPN 核心

1. 使用遥控器完成安装后的首次授权。
2. 启动和关闭 VPN，不需要手机或键盘。
3. 连接后至少一种内容入口可用：YouTube 应用或浏览器。
4. 无浏览器和无 GMS 时明确报告缺失能力。
5. 国内视频应用和投屏不被误代理。
6. 待机、唤醒和 Wi-Fi 切换后状态可恢复。
7. 已有其他 VPN 时提示用户切换。
8. 卸载一个曾加入分流选择的应用后，`vpn_apps` 偏好中的陈旧条目被清除；
   重装同名应用后按当前偏好正确进入分流或直连，不残留卸载前的旧决定。

### 电视浏览器增强

1. 遥控器可完成打开、搜索、播放、全屏和返回。
2. 手机扫码可输入文字和 URL。
3. 视频播放不因焦点切换中断。
4. 不支持 DRM 或区域限制时给出明确原因。

## 10. 商业判断

电视端可能比开发者工具更容易收费，因为：

- 用户目标明确
- 使用频率高
- 家庭大屏体验有直接价值
- 普通用户不愿意研究系统 VPN 和浏览器兼容

但它的风险也更高：

- 平台审核更严格
- 浏览器兼容成本高
- 设备碎片化严重
- 无法承诺所有电视都能使用 YouTube

因此电视端应采用：

- 核心 VPN 收费
- 浏览器增强单独收费或作为高级版
- 明确支持设备清单
- 不支持的设备直接提示，不卖“可能能用”
