# 汪连 ArchieLink｜外网访问专家 — 商业逻辑与付费边界

**状态：** Proposed  
**日期：** 2026-11-05  
**产品规格：** [SPEC.md](SPEC.md)  
**路线图：** [ROADMAP.md](ROADMAP.md)

## 1. 结论

这个付费 Skill 不必然是智商税，但“把安装提示词卖钱”一定是。

成立的前提是：

> 用户付费购买的是可验证的安全执行、自动回滚、跨平台适配、持续维护和支持，而不是模型本来就能生成的命令清单。

如果产品只是：

- 告诉用户安装 `wgcf`
- 生成一份 WireGuard 配置
- 复制几条 shell 命令
- 让 Agent 自己临场排错

那么它很容易被通用大模型替代，也更接近一次性咨询或提示词商品，不适合作为长期付费产品。

## 2. 用户推断中成立的部分

“推理能力达到一定基线的大模型可以自己探索解决方案”这一判断，在以下条件下大体成立：

- 用户只有一台已知设备
- 用户有管理员权限和 shell
- 用户能看懂网络错误
- 用户接受调试过程中的短暂断网
- 用户只追求一次性成功，不需要长期维护
- 模型可以读取系统状态并反复试错

在这个场景里，一个能力足够的通用 Agent 确实可以复现安装过程。基础知识和常规命令不构成长期护城河。

因此，不应把以下内容放在付费墙后：

- WARP 是什么
- 为什么需要 WireGuard
- 一般安装步骤
- 常见错误解释
- 单台已知设备的一次性 happy path

这些内容适合免费体检、获客和建立信任。

## 3. 用户推断中不成立的部分

“既然模型能推理，那么产品只写简单引导就够了”把“生成方案”与“可靠执行”混为一谈。

通用模型可以生成方案，但不天然保证：

- 启动失败后恢复原路由和 DNS
- 不覆盖用户原有 Shadowsocks 或其他 VPN
- 区分 IPv4 / IPv6、代理、DNS 和本地服务故障
- 在多网卡、休眠唤醒、网络切换后保持一致
- 处理企业防火墙、EDR、MDM 和权限限制
- 在 macOS、Windows、Linux 上使用不同的系统 API
- 为鸿蒙提供签名 HAP 和系统 VPN 授权流程
- 对错误码、回滚、升级和兼容性负责
- 提供退款、支持和后续修复

模型可以搜索到“答案”，但不会自动承担一次错误路由配置导致整机断网的责任。

## 4. 本机安装经历证明的复杂度

2026-10-26 的真实安装不是一次简单命令调用，而是经历了多轮环境相关故障：

1. Cloudflare 官方客户端要求 macOS 14，本机是 macOS 12。
2. Homebrew 安装因系统版本和网络重置失败。
3. 第一次 `wg-quick up` 接管默认路由和 DNS，但 IPv6 端点无法握手，导致整机断网。
4. 改用 `Table=off` 隔离配置后，才找到当前网络可用的 IPv4 端点。
5. 全隧道建立后，Google 仍失败，原因是 DNS 仍走本地。
6. 启用 WARP DNS 后，`api.deepseek.com` 被解析到不服务该 API 的 CloudFront 边缘，返回 403。
7. 最终加入 DeepSeek 专用本地 DNS、启动健康检查和失败自动回滚。
8. 还修复了 `wireguard-go` 随启动 shell 退出、重复开关和残留配置问题。

这些不是模型“不会写命令”，而是环境差异、破坏性操作和恢复责任。通用模型可以协助探索，但每次都要重新承担发现、验证和兜底成本。

## 5. 什么情况下它真的是智商税

如果验证后发现以下事实，应停止收费版本：

| 信号 | 判断 |
|---|---|
| 目标用户用通用 Agent 一次提示即可完成 | 提示词付费价值不足 |
| 失败时用户自己恢复网络没有明显成本 | 自动回滚价值不足 |
| 产品只需维护一份 Markdown | 没有持续维护价值 |
| 跨平台仅靠改名，实际没有适配 | 跨平台叙事不成立 |
| 付费内容主要是公开安装教程 | 应免费 |
| 用户不愿为省时间、降低风险或支持付费 | 需求不足 |
| 退款和客服成本高于收入 | 商业模式不成立 |

如果只面向会写代码、会看日志、愿意折腾的开发者，这个产品很可能很难收费，因为目标用户本身就在模型能力覆盖区内。

一次性数字激活在履约后可以按平台规则和消费者权益条款设计为已消费服务，但不能由代码单方面
宣告“永不退款”。售后政策必须与 SkillHub 规则一致，并保留退款、拒付和人工撤销后的停权能力。

## 6. 谁才可能愿意付费

付费用户更可能是：

- 不熟悉网络排障的普通用户
- 需要在多个平台和 Agent 上保持一致的人
- 不能接受整机断网或配置残留的人
- 需要鸿蒙伴侣应用、签名和系统授权的人
- 需要售后、升级和兼容性维护的人
- 需要在办公环境中避免破坏公司网络策略的人

他们购买的是：

- 少花时间
- 降低风险
- 明确支持边界
- 失败可恢复
- 后续有人维护

### 电视用户的特殊价值

Android TV 和 HarmonyOS 智慧屏是比开发者工具更直观的收费场景：

- 用户目标是直接观看 YouTube 或其他外网视频
- 大屏观看价值容易理解
- 普通用户不愿意研究系统 VPN、GMS、浏览器和遥控器兼容
- 电视端成功后使用频率高，付费理由持续存在

但电视端不能只卖“VPN 已连接”。如果设备没有 YouTube、Google 服务或可用浏览器，用户仍然看不到内容。产品必须检查内容入口，并把完整电视浏览器作为 V1.0 后的高级能力单独交付。

### 跨设备协助的价值

真实验收过程也暴露出跨设备操作门槛：普通用户不知道另一台电脑的 IP、登录名，也不应该手工配置 SSH 和 `authorized_keys`。

一次配对、只读诊断、自动清理可以成为明确的付费能力，尤其适合家庭多设备、Windows/Linux 辅助和电视接入。但产品必须坚持语义化 RPC，而不是把任意远程 shell 包装成便利功能。

手机、平板和电视的 D-track 开发者辅助必须假定用户具备基本动手能力：能在指导下打开官方调试模式、完成设备配对和 VPN 授权，并信任 AI 工具与产品团队。独自无法完成时，可以提供远程语音/屏幕指导，但目标不是服务完全无动手能力、要求零确认或静默授权的小白用户。无需配置 SSH 不等于无需用户操作。

## 7. 推荐商业模式

**决策状态：** Accepted v1，2026-11-06。采用“免费诊断 + 按次安全激活/修复 + 本地永久版 + 可选云增值订阅”的混合结构。

### 免费层

- 只读网络体检
- 通用安装建议
- 配置预览
- 兼容性判断
- 引导式手动步骤

免费层的作用是证明问题、建立信任和筛选需求，不承担“必须一键成功”的承诺。

### 付费层

- 已验证平台的一键执行
- 启动前快照
- 启动后健康检查
- 失败自动回滚
- 签名安装包
- 平台适配和版本维护
- 兼容性升级
- 支持渠道
- 鸿蒙/PC 伴侣应用

### 产品结构与成交单位

| 层级 | 成交单位 | 说明 |
|---|---|---|
| 免费 | 单次诊断 | `detect`、`plan`、`doctor` 和风险解释 |
| SkillHub Pay | 一次安全激活/修复任务 | 不按每次连接收费；一次任务包含执行、验证和失败回滚 |
| 个人永久版 | 当前大版本 | 一名个人用户、2 台自有设备、当前大版本永久使用、12 个月更新与支持 |
| 家庭年度订阅 | 时间 | 每年 12 台设备授权池，面向个人、家庭成员和朋友的非商业使用 |
| 其他云增值 | 时间/企业合同 | 远程只读支持、企业策略、更高设备额度 |

“永久”不得解释为无限期免费维护所有未来大版本。年度订阅也不能只卖“允许连接”的开关，必须对应真实持续服务。

家庭年度订阅的设备池规则：

- 每个订阅年度最多绑定 12 台不同设备，最多同时激活 12 台。
- 同设备同密钥重装不重复计数；换机或重置设备密钥消耗新名额。
- 每滚动 7 天最多新增 3 台，避免把家庭计划当作商业代装池。
- 亲友个人设备可非商业使用，但禁止收费代装、转售、出租、公开账号和批量部署。
- 账号持有人可移除设备；撤销后安全恢复命令仍然可用。

12 台方案的价值在“一个账号帮家人朋友减少配置风险”，不是提供 12 条可转售的 VPN 库存。

### 独立个人永久许可证

这里的“独立”首先指**独立销售与履约渠道**，不等于 B2B：

- 个人永久版面向 B2C 用户，通过独立订单、许可证文件或激活码交付。
- B2B 使用单独的企业席位年度授权，不销售公开的消费者永久版。
- 三产品收款统一经支付宝 aipay「AI网页应用收款」（Vibe Pay，个人收款场景，无 50 元服务注册上限），脱离 SkillHub 按量付费通道的金额边界（2026-11-23 拍板）；Machine Pay 402 流程保留为按次兼容通道。

首发价格假设（待真实付费实验验证）：

- 安全激活/修复：¥19.9/任务；执行窗口 14 天（7 天租约 + 7 天离线宽限），期内可多次 `up`，1 台设备，不自动续费。
- 个人永久版：¥199/大版本。
- 后续大版本升级：建议按新购价的 40%–50% 设置。
- 家庭年度 12 台设备：¥69/年（2026-11-23 定稿）。

### 三档权益矩阵

| 权益 | 按次（¥19.9） | 个人永久版（¥199） | 家庭年度（¥69/年） |
|---|---|---|---|
| `network_apply`（up/down/status/rollback） | 有 | 有 | 有 |
| `export_private`（完整导出/二维码） | 无 | 有 | 有 |
| 执行窗口 | 14 天硬窗口（7+7），到期需重新付费 | 7 天租约 + 30 天宽限滚动续租 | 7 天租约 + 30 天宽限滚动续租 |
| 设备数 | 1 台 | 2 台 | 12 台池（12 台/年，3 台/7 天） |
| 续租 | 不可续 | 可续 | 可续（每年手动付费） |

### 收款通道选型（2026-11-23 调研，2026-11-24 切换即刻收直连）

三产品统一走**支付宝 Vibe Pay「即刻收」直连模式（`alipay.aipay.nowpaydirect.*`，个人收款场景）**：商品（含价格/收费模式/档位名称）在支付宝「即刻收」管理小程序配置托管，控制面只绑定 plan → out_product_id，终端内二维码扫码支付。三种收费模式与三产品 1:1 对齐（次数包 COUNT ¥19.9 / 买断 ONE_TIME ¥199 / 时长包 YEAR ¥69）。原方案 `alipay.trade.page.pay` 因签约需自建电商三页+截图送审（首验 40006）搁置为后备。调研对比：

| 通道 | 结论 |
|---|---|
| 即刻收直连（nowpaydirect） | **采用（2026-11-24）**：三收费模式与三产品 1:1 对齐；商品/购买页/权益/核销支付宝托管，无签约送审死结；`purchase.consult`/`quota.query` 服务端确认到账，无异步通知依赖；external_buyer_id=InstallID |
| Vibe Pay 网页收款（`alipay.trade.page.pay`） | 后备（签约已提交待生效）：官方支持个人收款；「电脑网站支付」签约已于 2026-11-24 在 aipay 平台提交（MCC `A0007_B0125`、材料三页截图、应用复用 `2021007117679181`），SUBMITTED 等待生效——生效后 40006 消除，可生产验证后转正选；代码保留 |
| Machine Pay（按量付费） | 服务注册单价硬上限 ¥50（aipay 控制台表单原文），无法承载 ¥69/¥199；保留为按次 402 兼容通道 |
| PC Agent Pay（办公智能体支付） | 买家侧产品；商家侧数字资源路由回 Machine Pay（¥50 封顶），不解决金额上限 |
| SkillPay | 个人可上架、无金额上限、实时到账，但一次性付费需交付 Skill 明文、无商家 webhook，订单→租约只能人工兑换码衔接 |
| Token Pay（AI 连续订阅） | 仅限支付宝企业账号，个人开发者被挡；家庭年度改为每年手动续费 |

价格不是已证明的市场结论，只用于首轮价格测试；每档必须有可解释的权益差异。

定价对照（观察日期 2026-11-06）：

- [Sublime Text](https://www.sublimehq.com/sales_faq)：个人 $99 一次性授权，含 3 年更新，之后永久使用最后版本；商业版按席位年度订阅。[商店页](https://www.sublimehq.com/store/text)显示商业版 $65/席位/年起。
- [JetBrains perpetual fallback](https://sales.jetbrains.com/hc/en-gb/articles/207240845-What-is-a-perpetual-fallback-license-and-how-do-I-use-one)：连续订阅 12 个月后，可永久使用订阅开始时的大版本及小版本；新增大版本仍须续订。

这两个案例支持“永久使用当前版本 + 有期限更新 + 商业席位订阅”，而不是“一次付费永久更新所有未来版本”。

个人永久版权益：

- 一名实名个人用户，2 台本人日常使用设备。
- 当前大版本永久使用，不因停止订阅失效。
- 购买后 12 个月内提供功能、安全更新和基础支持。
- 12 个月后继续使用最后获得的版本，不保证新系统、新 WARP 端点和第三方服务持续兼容。
- 免费诊断、`down` 和 `rollback` 永远可用。
- 每年允许 1 次设备更换；丢失、报废或换机可释放旧设备。
- 不含 12 台家庭设备池、云端多设备面板、电视/鸿蒙远程配对、企业策略和优先支持。
- 仅限个人非商业使用；公司、机构、收费代装、转售和批量部署必须购买企业授权。

B2B 企业授权：

- 按席位/设备年度订阅，不使用消费者永久版。
- 5 席起，按报价；提供企业抬头、发票、设备管理、离职回收和版本冻结策略。
- 可提供年度维护、兼容性支持、MDM/企业网络策略和 SLA 作为增值项。
- 如客户要求离线或私有部署，单独签企业永久授权 + 年度维护合同，不公开标价。

### 渠道冲突控制

| 风险 | 控制 |
|---|---|
| 永久版侵蚀家庭订阅 | 永久版只含 2 台自有设备、无云面板和家庭池 |
| 永久版侵蚀按次修复 | 按次后 30 天内升级永久版，可抵扣该次费用 |
| 按次 export 激活第二台设备 | `export_private` 仅永久/家庭签发，按次与免费用户完整导出/二维码 exit 4（2026-11-23 拍板） |
| 按次窗口过长稀释永久版价值 | 14 天硬窗口（7 天租约 + 7 天宽限），到期需重新付费 |
| B2C 永久版被企业采购 | 明确个人非商业许可；企业必须转年度席位授权 |
| 停更后的旧版本带来安全和兼容风险 | 12 个月更新期后标注支持边界，引导升级 |
| 家庭年度订阅被当成代装生意 | 12 台/年、3 台/7 天、设备密钥绑定和反转售条款 |
| 永久版与家庭版功能重叠过多 | 云端控制面、设备池和远程支持只进入订阅 |

永久许可证不应包含未来所有大版本。它卖的是“不会断供的当前版本”和“有期限的维护责任”，不是永久免费维护无限未来。

### 商业资产边界

真正不可替代的商业价值不是 WireGuard 命令，而是：

1. 本地共存判断、受保护端点、快照、健康检查和确定性回滚。
2. 跨 macOS、Windows、Linux、鸿蒙和电视的兼容维护。
3. 设备绑定租约、撤销、退款、滥用处置和更新通道。
4. 出故障时由产品承担责任，而不是把恢复工作丢回用户。

公开诊断知识不会毁掉付费价值；把基础诊断锁起来反而降低转化。

不建议只卖：

- 一段提示词
- 一份 WireGuard 配置
- 一个通用 shell 脚本
- 一次性的模型对话

## 8. 最低开发量路线

开发顺序不应该是直接构建全平台大产品。

推荐先做：

1. 通用 Agent 也能完成的免费诊断。
2. 一个受控的 macOS 安全执行器。
3. 自动回滚和真实故障注入。
4. 小范围付费试验。
5. 只有付费需求成立，再投入 Windows、Linux、鸿蒙和支付系统。

如果第一步就发现用户只需要一段提示词，那么应把它作为免费内容发布，不继续构建付费产品。

## 9. 最低验证实验

在正式开发前，用同一批目标用户比较两种方式：

- A 组：只给通用 Agent 和“帮我配置 WARP”的提示。
- B 组：给受控 Skill 和固定诊断、执行、回滚流程。

记录：

- 是否成功连接
- 用时
- 是否需要人工排障
- 是否断网
- 是否能恢复原网络
- 是否需要开发者介入
- 用户是否愿意付费
- 用户愿意支付的价格区间

建议的 go/no-go 门槛：

- 如果 A 组大多数用户在短时间内成功，且没有破坏网络，付费核心价值不足。
- 如果 A 组成功但经常断网、不会恢复或需要反复排障，安全执行器有真实价值。
- 如果 B 组能显著减少支持请求和恢复成本，才值得继续开发。

这些是需要实测的数据，不是当前已证明的市场结论。

## 10. 产品决策

当前采用以下假设继续规格设计：

1. 免费层出售“知识和诊断”不现实，应作为获客。
2. 付费层只卖可靠执行、回滚、维护、签名和平台支持。
3. 如果通用模型能稳定替代，就删除付费产品，不强行寻找收费理由。
4. 不把“模型不够聪明”当作商业壁垒；壁垒必须是工程、测试、支持、分发和信任。
5. 在真实用户验证前，不投入鸿蒙伴侣应用以外的移动原生开发。
6. 核心网络执行留在本机，云端只做授权、订单、设备和持续增值。
7. SkillHub 原生按次能力用于“安全激活/修复”，永久版和云订阅需完成平台规则确认后另行提供。
